# Restricted frame import evidence

The optional Chromium patch `browser/chromium/patches/resident-frame-import.patch` applies **after** `resident-document-provenance.patch`. Build and pin a new Fawn executable and its dependency closure before collecting evidence. The frame-only switch leaves the renderer’s existing submit/flush path in place. It adds no track settings call, GPU wait, readback, or debugger.

Run the usual private, sandboxed `resident-comparison.py run` with its pinned profiles and `--source-receipts STOCK FAWN --frame-import-evidence`. Both Fawn arms collect metadata from their own browser over its private CDP pipe. The capture chooser and the workspace’s permission checks still apply. The harness writes the trace after recording verified completion. The report checks each finished row, or run `python3 check-frame-import.py ROW` in this directory. A missing event, unmapped browser image, ambiguity, or changed grant keeps the input unproven. These traced rows remain diagnostic.

Only the original restricted processor’s Blink VideoFrame wrapper carries its native component and creating isolated-world ID. Wrappers constructed by script, transferred streams and frame clones begin without that tag. A fresh or cached WebGPU import from that world records the actual document, component, source epoch, crop revision, and the wrapper’s timestamp. The controller independently binds the selected observation to its grant, session and ordinal. The checker joins it to the browser’s accepted restriction and checks for a source switch or revoke before that import. The private trace allowlist contains those identities and timing metadata. It records no pixels, media bytes, page text or URLs.

A positive receipt establishes that Blink returned an external texture for the restricted input in that row. It cannot establish that the tile-diff pipeline consumed this external texture, which native backend completed that command, or the uninstrumented latency. The remaining native facility must link the imported resource through the bound pipeline and command buffer, through the real wire batch, to a successful driver fence or timeline value for that same submission. It must distinguish cancellation, device loss, and an unresolved submit without introducing an extra wait or altering normal batching. Run the disabled-Doe control and measure observer overhead separately. The existing GDB diagnostic retains its own scope and never supplies evidence for another row.
