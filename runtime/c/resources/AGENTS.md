# Resource ownership

Follow the common C guide and parent charter. This owner adopts real native
resources; never create a synthetic backend or publish borrowed native storage
as owned. Preserve same-device identity, transactional acquisition, first-error
recording and unknown-submission obligations. Keep map/future delivery, labels
and diagnostics in their existing owners. Normalize named format semantics at
native ABI adapters: retained Zig/header numeric identities currently differ.
The focused check is `make -C runtime/c/resources check`; outputs belong in `/tmp`.
Render attachment begin/end packets must bracket every query event, including
empty scopes. Never infer pass closure from the last draw. Map completion pointers
start at the admitted span; const/read admission must not become writable storage.
Bundle replay clears logical bindings even for zero bundles; do not copy retained
Vulkan's internal save/restore into public state. Keep each bundle self-contained
and reuse pass draw admission and packets rather than another renderer.
Float32 filterability is an enabled WebGPU feature, not a driver capability.
Keep copied binding feature admission in the group owner through submission.
Shared dispatch/draw scope validation owns cross-binding aliases: buffer usage is whole-object,
while writable storage aliases additionally use resolved byte ranges. Never replace
this with backend handle equality or frontend-only pair checks.
Render-pass scopes include every setter and executed bundle, even overwritten,
unused or empty ones. Transfer retained scope storage to immutable end records;
logical unbind/reset must not erase usage. Query descriptor count is 0..4096;
zero-count logical identities need no native pool but cannot write or resolve.
Nullable vertex unbind validates its zero buffer range without deleting historical
scope uses. Occlusion indices are single-write per pass, not per command buffer;
keep this logical admission separate from backend query reset/availability.
