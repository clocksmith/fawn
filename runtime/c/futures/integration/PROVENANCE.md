## Instrumentation and first failures

GCC/G++ 14.2.0 compiled all C futures/bridge code; retained Zig used the existing
0.15.2 toolchain. ASan+UBSan bridge and original C API tests passed with leak
detection disabled. The first ordinary ASan run is retained: LeakSanitizer failed
because this execution environment is traced. The subsequent receipt explicitly
uses `ASAN_OPTIONS=detect_leaks=0`; it is not a leak-detection pass. TSan bridge
and original real-condition/concurrent-pump C tests passed. These observations
instrument GCC C owner/private bridge and C/C++ callers only. They do not
instrument or qualify all retained Zig memory, lifetimes or synchronization.

Other first failures are retained, not relabeled:

- The first timing command could not run because `/usr/bin/time` is absent;
  the portable Python capture helper replaced that unavailable wrapper.
- One shell preparation initially used repository-relative paths from the Zig
  subdirectory and failed before writing/running the helper. It was corrected
  to the actual repository root; no native outcome was inferred from it.
- `default-build-04.json` compiled the default shared artifact but could not
  install generated metadata after disposable cache objects had been removed
  while their cache index remained. Invalidating only the new author's cache
  index and rerunning produced `default-build-05.json`, which passed. This was a
  build-cache disposal failure, not a default-provider behavior failure.
