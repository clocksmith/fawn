## Source audit and repaired defect

C owns one checked allocation with completion storage queried from the accepted
public future API, not a second queue or a cast Zig Completion. Retirement is
snapshot -> typed deliver/resource cleanup -> accepted finish -> completion
deinit -> exact free -> event release. A separate full-readiness-call owner lease
outlives destruction of that event. Publish returns a saved ID after publisher.
Ownerless dispatch uses a separate mutable typed local, performs no allocation,
copy or publisher call, then obtains the legacy ID after callback cleanup.
Hooks may execute on producer/pump/wait/worker threads with caller-supported
shared state. Allocation failure means no allocation/ownership transfer, not
that an allocator callback cannot do bookkeeping.

Seven typed deliver/catch/resource families remain unchanged. Five imports,
the Metal opaque readiness-token transport/fallback and one guarded borrowedQueue
accessor implement the frozen seam. Original callback and future sources hash
exactly to the baseline. C owner implementation is 160 lines; native typed adapter
96 and selected facade 13. These are raw line counts, not a maintainability or
performance improvement claim.

Candidate1's allocator reconstruction used state.? and unjustifiably required a
non-NULL token even for stateless allocators with an unused undefined pointer.
Candidate2 repairs only native reconstruction to state orelse undefined, keeps
exact vtable and meaningful stateful identities, and adds a developer deferred
c_allocator case plus the mechanical layout hash. No fabricated pointer is used.
The independent supplemental deferred c_allocator wait/pump/final-destruction
case was sealed before candidate2 inspection and passed. C core/header/build
subset stayed unchanged. Lucky non-NULL undefined bits are not the oracle;
source semantics and unused stateless state are the governing rationale.
