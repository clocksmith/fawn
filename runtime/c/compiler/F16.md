# Binary16 developer surface

`enable f16;` selects binary16 scalar/vector/matrix semantics in the shared C
pipeline. `f16`, `vecNh`, `matCxRh`, generic half vectors/matrices and `h`
literals retain their own type and 16-bit constant payload; they are not f32
aliases. Natural scalar size/alignment is two bytes. Vector, matrix, array and
structure layouts derive from that scalar owner.

The constant owner rounds to nearest, ties to even; rejects nonfinite evaluated
constants; preserves signed zero; and does not depend on the host `_Float16` ABI.
Decimal/hexadecimal literals use the existing bounded rational parser with
binary16 precision. Automatic materialization remains distinct from explicit
numeric conversion. Existing source-linked errors and unpublished failure
outputs remain unchanged.

SPIR-V emits Float16 and the 16-bit storage/uniform capabilities, half typed
arithmetic, and explicit floating-width conversions. It does not request
StorageInputOutput16 while half stage interfaces are unsupported. MSL uses
`half`. Cross-width half bitcasts preserve low-to-high lane order in the shared semantic
owner and each target. HLSL uses explicit `float16_t` scalar/vector/matrix types, requiring an
appropriate native-16-bit DXC policy. Word-backed HLSL buffer helpers preserve
neighboring halves with masked atomic writes. Text emission is not SDK acceptance.

Device consumers pass `DOE_COMPILER_DISABLE_F16` unless the device requested
ShaderF16. The compiler rejects the directive when that flag is set; standalone
compilation without a device restriction admits the source extension. The flag
is retained through module validation/specialization. Public typed reflection
identifies half with `DOE_COMPILER_LEAF_F16` (7), leaving older scalar identities
unchanged.

## Focused verification

```sh
make -j1 -C runtime/c/compiler test-f16 SPIRV_VAL=/path/to/spirv-val
make -j1 -C runtime/c/compiler test-numeric-environment
```

`test-f16` exercises every finite binary16 payload, tie-even/subnormal/overflow
controls, device-disabled admission and untouched-output rejection. It compiles
four unchanged `bench/inference-pipeline/kernels/matmul_logits*` half consumers
to all three targets. Fresh SPIR-V is validated for Vulkan 1.1. Storage aggregates,
compact uniform half loads (including exact 2–34-byte odd-half tails with dynamic
indices), runtime interpolation/geometric builtins, cross-width bitcast roundtrips
and half specialization values are separate controls. Python binary16 packing
provides an independent literal and specialization oracle.

These are developer CPU/target-validation checks, not physical execution,
performance, full-language or production-default qualification. Retained frozen
milestone tests and source seals remain historical evidence; the compiler README
explains their named derived acceptance routes.

## Remaining implementation/qualification gates

- Half stage interfaces need their own owner admission and target/native
  composition.
- HLSL word-backed storage still needs native16 byte-address lowering and exact
  logical-length metadata for odd-half binding tails; native D3D12 ShaderF16
  admission must remain disabled until that producer/descriptor path is composed.
- Native MSL/DXC validation, physical backend execution and unchanged application
  qualification remain separate from C compilation and SPIR-V validation.
