# DXIL C parity: complete for the DXIL directory, with subset limits listed

This commit completes the DXIL directory in
`runtime/c/compiler/src/dxil/`. It follows the PARTIAL DXIL and TSIR
commit (c7e96c08) and the TSIR non-CSL commit (2fa21299). TSIR is
not changed by this commit, except that the Makefile test list is
unchanged for TSIR.

## What is complete

- All 9 Zig DXIL files: `runtime/zig/src/compiler/wgsl/emit/dxil/`
  (8 files, 2,765 lines) plus
  `runtime/zig/src/compiler/wgsl/pipeline/translate_dxil.zig`
  (74 lines), total 2,839 lines.
- Prerequisites built for this directory: C Doe IR
  (`dxil_ir.c/h`, `dxil_ir_query.c`), WGSL analyzer subset
  (`dxil_analyze.c/h`, `dxil_analyze_types.c`,
  `dxil_analyze_decl.c`, `dxil_analyze_stmt.c`,
  `dxil_analyze_expr.c`, `dxil_analyze_internal.h`), and HLSL
  emitter (`dxil_hlsl.c/h`, `dxil_hlsl_expr.c`,
  `dxil_hlsl_stmt.c`, `dxil_hlsl_internal.h`), plus diagnostic
  (`dxil_diagnostic.c/h`), native IR walk and full-module assembly
  (`dxil_native.c/h`, `dxil_native_walk.c`,
  `dxil_native_internal.h`), primary emit path with HLSL/DXC
  fallback (`dxil_emit.c/h`), and all four translate entry points
  (`dxil_translate.c/h`).
- Tests, Linux GCC 13.3.0, standalone flags, plus UBSan and ASan
  runs from the worker: md5 7, bitcode 64, container 55, validate
  53, builder_serialize 336, mapping_toolchain 230, ir_native 123,
  hlsl 13, emit 29, analyze_translate 45, total 955 checks,
  0 failures. Combined with TSIR in this tree: 955 DXIL plus
  388 TSIR, total 1343 checks, 0 failures. Run with:
  `make -C runtime/c/compiler test-dxil-tsir-partial` and
  `test-dxil-tsir-sanitize`.
- Key assertions from the worker: canonical compute WGSL
  translates to a 632-byte container validating with kind COMPUTE,
  4 parts, and a test-side bitcode scan showing exactly 1 function
  block with 3 CALL ops and a trailing RET; storage/barrier/
  arithmetic and vertex sources validate; exact HLSL text for
  canonical and storage modules; fake-DXC toolchain translate
  returns byte-identical output; empty/missing DXC executables
  yield ShaderToolchainUnavailable.

## What is still subset-limited, not hidden

See `src/dxil/gaps.md` items 9-16 and the worker gaps, including:
- Analyzer subset: struct types must be declared before use (no
  forward struct references); `for` loops fail UnsupportedConstruct;
  global initializers accept scalar literals only; matrix indexing
  falls back to the base type; `@id` values are validated but not
  stored (no IR field); no full sema type checking, no binding
  validation beyond group/binding presence, no `ir_validate`,
  robustness transform, or opt rewrite. Blocker for full frontend
  parity: porting the complete Zig frontend, which is larger than
  this directory's scope.
- HLSL subset: no helper prologue (atomic/pack/unpack fail
  UnsupportedBuiltin); vertex/fragment stage wrappers fail
  UnsupportedConstruct; ref-typed locals fail InvalidIr;
  runtime-array write guard not emitted.
- Fixed capacities (types 128, structs 32, functions 16, exprs
  512, etc., else OutputTooLarge); walk recursion cap 64 and
  parser recursion cap 256; query cycle guard (one pass, then
  null/false, instead of Zig looping); no thread-local diagnostic
  (explicit diagnostic pointer, NULL drops the message);
  arena-versus-allocator lifetime collapse (no heap allocation,
  caller-owned output, no leak in either variant); temp-file nonce
  is process id plus counter with O_EXCL instead of Zig's
  nanosecond timestamp; DXC read errors use strerror text;
  dispatch cbuffer laid out across lines instead of Zig's
  single-line form (whitespace only); float formatting may differ
  in the last digit for exotic doubles; emit-path diagnostic kind
  is always InvalidIr (Zig behavior, preserved); translate
  double-prefix diagnostic shape (Zig behavior, preserved);
  placeholder semantics preserved exactly (constant-0 refs/
  constructs, assign no-store, both `if_` branches,
  `address_of`/`deref` fail).
- Windows DXC runner still returns ShaderToolchainUnavailable
  (pre-existing gap, unchanged).
- No output was diffed against Zig-generated bytes: no Zig
  toolchain exists on this VM, so expectations were hand-derived
  from Zig semantics plus oracle tests (Python-hashlib MD5, fake
  shell-script DXC executables only). No real DXC, no GPU, no
  macOS, no Windows runs; no release, full-browser, or
  Doe-versus-Dawn claims.
- Sources are still NOT in `src/sources.txt` and NOT linked into
  `libdoe_compiler.so`, for the same strict-flag reason as in
  PARTIAL_DXIL_TSIR.md. That wiring, with strict-flag fixes, is
  remaining work, not claimed here.
- CSL excluded entirely, as before: 45 files, 16,033 lines, plus
  the 7 CSL-only TSIR files, quarantined, mapped not built.
- Fawn launcher gap untouched by this commit, and remains last,
  as its own small commit, if still present.
